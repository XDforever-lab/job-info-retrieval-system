## 第一章 引言（~1000 字）

### 1.1 项目背景
- 信息检索技术的核心价值：从海量非结构化文本中精准获取信息
- 招聘领域的信息过载问题：求职者面对数万条招聘信息难以高效筛选
- 垂直领域检索系统的意义：通用搜索引擎无法满足结构化+语义化的招聘搜索需求

### 1.2 选题原因
- 资源类型聚焦：招聘数据是结构化与非结构化混合文本，区别于课堂的人民日报新闻语料
- 语料规模适中：93,602 条原始数据 → 清洗抽样 5,000 条，足够支撑分类/聚类实验又保证 Web 端流畅
- 实际应用价值：模拟主流招聘平台的检索逻辑，展示效果强
- 知识覆盖全面：天然包含结构化字段与非结构化文本，适合多字段联合检索 + 文本挖掘

### 1.3 项目目标
- **理论课知识融合**：布尔逻辑检索、VSM、文献-语词矩阵、倒排文档检索、TF-IDF 加权、检索评价指标
- **实践课实验整合**：N-gram 统计、分词精标与评测、关键词抽取、文本分类、文本聚类
- **产品设计方法**：五层模型（战略→范围→结构→框架→表现层）指导系统设计

### 1.4 报告结构
- 简述后续各章内容与逻辑关系

## 第二章 数据与语料分析（~2000 字）

|------|------|----------|
| 企业名称 | 文本 | 精确/模糊搜索 |
| 股票简称 | 文本 | 别名匹配 |
| 上市公司行业 | 分类 | 行业浏览、分类筛选 |
| 工作城市 | 分类 | 城市筛选、地域统计 |

- 行业归并：81 原始类 → 9 大类

### 4.1 分词方案（~1000 字）

#### 4.1.1 问题与挑战

#### 4.1.2 七种分词器实现
- 机械分词：FMM（正向最大匹配）、BMM（逆向最大匹配）、BiMM（双向最大匹配）

- **BIES 完全匹配率**：逐条逐词位置完全匹配
- **集合匹配 P/R/F1**：集合视角的词级别评测

### 4.5 检索引擎（~1000 字）

#### 4.5.1 倒排索引构建
- 数据结构：Lexicon（词典）`{词条 → (DF, 倒排列表指针)}` + Posting List `[(docID, TF, [位置])]`
- 构建过程：遍历 5,000 条文档→ 逐词建立词典 → 记录文档 ID + 词频 + 位置
- 构建耗时：~0.9 秒（38,288 词条）
- 顺排 vs 倒排性能对比：同一查询倒排快 33-72 倍
- Sutton 四种加权方案（ltc/nfc/nfx/bfx）对比

#### 4.5.2 多字段联合检索
- 查询处理：用户输入 → Jieba 分词 → 去停用词 → 布尔检索候选集 → VSM 相似度
- 最终得分公式：`Score = 0.5 × sim_title + 0.4 × sim_desc + 0.1 × bonus_company`
- 标题字段×2.0 加权、企业名称匹配 +0.1 加分

#### 4.5.3 布尔过滤
- 字段级精确过滤：行业 IN / 城市 IN / 学历 IN / 经验 IN
- 区间过滤：最低月薪 ≥ / 最高月薪 ≤ / 发布日期 BETWEEN
- 筛选条件之间 AND 关系

#### 4.5.4 排序与分页
- 四种排序：相关度 ↓（默认）/ 发布日期 ↓ / 最低月薪 ↓ / 最高月薪 ↓
- 分页：每页 20 条

#### 4.5.5 关键词高亮与摘要
- 查询词 `<mark>` 高亮（黄色背景 + 加粗）
- 长词优先匹配（避免"机器学习"被"机器"和"学习"分别高亮）
- 上下文片段提取（前后各~75 字）

## 第六章 总结与反思（~800 字）

### 6.1 项目成果总结
- 完成了一个从数据清洗到 Web 上线的完整信息检索系统
- 量化的检索性能指标（MAP 0.93 / NDCG@10 0.96）
- 理论课全部核心知识点的实践验证
- 六次实验完整融入系统

### 6.2 理论知识与实践能力收获
- 信息组织：倒排索引从理论到工程实现的完整理解
- 信息检索：VSM + TF-IDF + 布尔过滤的组合检索策略设计
- 信息评价：P@K / MAP / NDCG 等多维度评测体系
- 系统思维：五层产品设计模型指导下的端到端开发
- 团队协作：2 人小组分工与版本管理

### 6.3 不足与改进方向
- 分类准确率偏低（微观 F1=25%）：训练数据仅 400 条，远不足以支持 9 类分类
- 检索语义理解有限：基于词袋模型的 VSM 无法捕捉"前端开发"与"React 工程师"的语义等价
- 未实现短语查询与通配符查询
- 用户测试样本量偏小
- 改进方向：BERT 语义检索、主动学习扩展训练集、phrase query 支持

### 6.4 AI 参与声明
- 明确标注 AI 辅助范围 vs 个人实现部分

| 类型 | 范围 | AI 参与程度 |
|------|------|------------|
| 个人核心实现 | 分词算法逻辑、倒排索引数据结构设计、评测方案制定、检索策略公式设计 | 无 AI 参与 |
| AI 辅助实现 | 前端 HTML/CSS/ECharts 配置、Boilerplate 代码、Bug 调试 | AI 生成，人工审查修改 |
| AI 生成 | 部分文档初稿润色 | AI 辅助写作 |
